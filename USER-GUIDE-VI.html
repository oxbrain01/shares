Executive Summary — Tóm tắt điều hành

Pentest Team cung cấp hai lớp bảo mật bổ sung cho ứng dụng của khách hàng, vận hành hoàn toàn trên hạ tầng MSP — khách hàng không cần host runner, engine quét hay nền tảng AI.

Lớp A — Security Assurance Pipeline (L1–L9): Shift-left tự động trên mỗi push/MR, phát hiện sớm secret, pattern, dependency và runtime risk; chỉ publish metadata (file, line, severity).

Lớp B — AI Audit Pentest: Audit sâu theo lịch hợp đồng hoặc trước go-live — phân tích logic nghiệp vụ, chuỗi tấn công đa bước và xác minh khai thác có kiểm soát (RoE).

01

Zero customer infra

Khách chỉ cần GitLab + repo + quyền Maintainer

02

No source exfiltration

Mã không rời VPC khách qua artifact công khai

03

White-label assurance

Log chỉ hiển thị [Assurance][Lx]

04

Dual-layer coverage

CI liên tục + AI audit định kỳ / pre-go-live

§01 Hai sản phẩm trong một nền tảng

Hai lớp bảo mật bổ sung — không thay thế lẫn nhau.

§03 Phân vai: Khách hàng vs Pentest Team

Bảng RACI — trách nhiệm rõ ràng theo chuẩn engagement audit.

Hạng mục Pentest Team (Admin) Khách hàng
Runner GitLab R/A C — cấp token
Image security-runner R/A I
Máy chủ L1 (layer-quality-analysis) R/A I
Cổng giám sát + tenant R/A C — webhook secret
AI Audit Pentest R/A C — scope + RoE
GitLab + repository I R/A
Merge module CI C R/A
CI/CD Variables C — gửi giá trị R/A — paste masked
deploy-staging.sh C — template R/A — implement
Staging URL I R/A
Remediation findings I R/A
DPA (L1 — lưu mã phân tích chất lượng) R — cung cấp A — ký (Plus+)

R = Responsible · A = Accountable · C = Consulted · I = Informed

Phạm vi loại trừ — Khách không bao giờ phải làm
  • Cài GitLab Runner · Build image quét · Cài máy chủ L1 / engine L8 / nền tảng AI Audit
  • Mở egress ra SaaS scanner công cộng
  • Commit token/password vào assurance.variables.yml

§05 Quy trình onboarding

SLA Pentest Team: ≤ 1 ngày làm việc sau khi khách hoàn thành bước 1–4.

Bước 0 — Integration Kit

SECURITY_RUNNER_IMAGE:   <ECR URI>:1.0.10
NAT_EGRESS_IP:           x.x.x.x
L1_PROJECT_KEY:          acme-api  (Plus+)

Bước 1 — Cấp quyền GitLab

Maintainer · Runner token → gửi Admin qua kênh bảo mật.

Bước 2 — Merge module CI

Review MR hoặc quick-deploy --mode=nested --entry=core.

Bước 3 — Paste GitLab Variables

Masked + Protected. Không commit secret vào YAML.

Bước 4 — Chuẩn bị file stack

l1-project.properties, .assurance-credential.toml, Dockerfile.

Bước 5 — Push lần đầu

Job platform-preflight phải pass.

Bước 6–8 — Verify & Handoff

Pentest Team: runner, L1, portal · Dashboard + lịch AI Audit.

.gitlab-ci.yml tối thiểu

variables:
  DEVSECOPS_MODULE_DIR: devSecOps-module
  SECURITY_RUNNER_IMAGE: "<ECR URI từ Integration Kit>"
include:
  - local: devSecOps-module/pipelines/entry.core.yml
  - local: assurance.variables.yml   # PHẢI đứng SAU entry
Lưu ý quan trọng

assurance.variables.yml phải include sau entry.*.yml.

Biến GitLab Masked Gói
MSP_TENANT_ID, MSP_PORTAL_WEBHOOK_URL No Tất cả
MSP_WEBHOOK_SECRET, L1_TOKEN, DAST_BEARER_TOKEN Yes Theo gói
L1_HOST_URL, L1_PROJECT_KEY, DAST_WEBSITE_URL No Plus+ / Enterprise

§06 Vận hành hàng ngày

Developer

  • git push / MR → pipeline tự chạy
  • Đọc findings trong artifact
  • Sửa theo file + line
  • Pre-commit hook (khuyến nghị)

DevOps

  • GitLab Variables khi đổi secret
  • DAST_WEBSITE_URL khi staging đổi
  • Review assurance.variables.yml
  • Approve deploy-production

Security team

  • Triage findings → ticket + owner + SLA
  • Yêu cầu AI Audit (scope + RoE)
  • Sign-off release sau gate pass

Merge Request L1–L5 + gate — không L6/L8/deploy < 30 phút
Default branch Full: build + L6 + L8 + deploy 30–90 phút

§08 AI Audit Pentest

Tiêu chí Pipeline CI AI Audit
Tần suất Mỗi push/MR Theo lịch / on-demand
Độ sâu Rule + signature AI reasoning + multi-agent
Dynamic L8 baseline Xác minh khai thác có RoE
Thời gian 5–30 phút 1 giờ – 2 ngày
Output assurance/*.json Báo cáo + scorecard

T-3 ngày

Scope · RoE · staging URL · test account · on-call.

Trong audit

Không breaking deploy · phản hồi ≤ 4h.

T+5 ngày

Triage · remediate · re-audit Critical/High.

Finding CI AI Audit bổ sung
L2 pattern Logic exploit, chuỗi tấn công đa bước
L3 secret CI/CD, history, config leak
L4/L5 CVE Reachability thực tế
L8 runtime Xác minh dynamic có RoE
Business logic AI trace flow

§10 Biến GitLab

Ưu tiên: GitLab Variables → assurance.variables.yml → defaults.

variables:
  ENFORCEMENT_MODE: soft
  ASSURANCE_MR_FAST: "true"
  FAIL_ON_SECRET_LEAK: "true"
  FAIL_ON_CRITICAL: "true"
  L5_ENABLED: "false"

Production: unset ENFORCEMENT_MODE, FAIL_ON_DAST: true (Enterprise).
